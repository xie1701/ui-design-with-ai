# 质量边界、证据与停止规则

## Visual Critic

Visual Critic 只评截图可见内容。0–10 分是用于同一任务前后比较的 heuristic，不是跨项目认证；不可见或证据不足的维度写 `N/A`，不进入总分。

- **0–3**：可见任务或视觉系统不成立。
- **4–5**：可阅读，但层级、身份或细节明显粗糙。
- **6–7**：方向成立，仍有模板感或关键视觉缺口。
- **8–9**：在当前截图与目标情境内成熟、一致、有鲜明判断。
- **10**：极少使用；仅描述视觉证据，不代表生产验收。

不要用分数的微小变化证明进步；优先比较结构性差距、阻断项清零和成对截图。

## Engineering QA

工程验收不打审美分。每项只允许：

- `PASS`：有可复核证据通过。
- `FAIL`：有证据失败，属于阻断或待修。
- `N/A`：该任务不适用，说明理由。
- `NOT TESTED`：适用但没有完成验证，不能视为通过。

至少记录：项目、适用性、方法、环境、结果、证据位置、责任人/执行者、日期、备注。使用 [`qa-template.md`](qa-template.md)。

## 停止状态机

每轮必须选择一种状态：

| 状态 | 条件 | 下一步 |
|---|---|---|
| `pass` | 适用验收项证据充分，阻断项清零，剩余风险已接受 | 交付 |
| `blocked` | 缺输入、权限、环境、依赖或安全许可 | 记录解除条件并停止自动循环 |
| `plateau-visual` | 连续轮次仅局部变化，核心视觉差距未缩小 | 回 Develop 换方向/身份 |
| `invalid-problem` | 证据显示问题定义错误或任务无价值 | 回 Define |
| `budget-exhausted` | 达到预设轮数、时间、token 或费用上限但未通过 | 人工接管，不得标 pass |

“3 轮”只是常见预算 heuristic；它只终止自动循环，不自动判定通过。方向数、并行实例数、参考图数量和 Critic token 比例同样按任务风险和资源调整。

## 建议仲裁

Critic 不因实现成本降低视觉标准；Orchestrator 负责对每条建议记录：

- `impact`：对任务/视觉质量的影响。
- `feasibility`：当前技术与时间内是否可行。
- `risk`：性能、可访问性、品牌、许可或回归风险。
- `evidence`：支持接受/拒绝/延期的证据。
- `decision`：accept / reject / defer。

## Web QA 最小覆盖

按适用性选择，不适用写 N/A：

- 主要任务、下一步、当前状态。
- 适用的 default/hover/focus/pressed/loading/empty/error/success/disabled/permission 状态。
- 320px、目标移动宽度、平板/桌面断点与长文案；不得仅凭全页截图判断。
- 键盘顺序、focus-visible、语义 HTML、label、错误关联、读屏关键路径。
- WCAG 2.2 项目要求对应的文本、控件、焦点与非文本对比度。
- reduced-motion、动画暂停/降级；关键信息不只存在于动画。
- lint、typecheck、build、关键路径自动化与目标浏览器。
- 资产尺寸、fallback、授权、密钥边界和性能预算。
- 任务走查或真实用户测试；未做必须写 NOT TESTED，不能由 Critic 分数替代。
