# 案例 · 青禾艺术「听见」提案落地页

把一份 10,616 字节的中文产品提案（markdown），做成一个**可以走一遍**的单文件互动落地页。

> **这份案例已脱敏。** 原件是一个真实客户的提案；机构名、客户称谓、所在城市与联系方式已替换为占位值（`青禾艺术` / `李老师` / `本地` / `138 0000 0000`）。视觉、结构、论述与全部 102 条文案的**字数与语气均未改动**，只换了标识性名词。替换是**一对一字符串替换**，可机器复核：见 [`docs/redaction.md`](docs/redaction.md) 与 [`scripts/verify-redaction.py`](scripts/verify-redaction.py)。
>
> 一处必须说明的副作用：页面里有几条声纹图形是由**文本散列派生**的，机构名一换，图形形状就跟着变。所以本仓库的 `index.html` 与私有原件在文案上等价、在派生声纹形状上不同。

- 源文档：`proposal-source-v1.1.md`（102 条文案，私有副本，未随仓库分发）
- 成品：[`index.html`](index.html)（单文件、零外部依赖、零网络请求，直接双击可开）
- 模式：`CREATE` + `COMPONENT`，六阶段全跑
- 硬约束（用户明示）：**文案主体不得缺失或修改**

## 这个案例特殊在哪

前两个案例是「从需求出发做页面」，这个案例是「从**一份必须一字不改的文档**出发做页面」。两者要解决的问题不一样：

| | 前两个案例 | 本案例 |
|---|---|---|
| 内容从哪来 | 自己写 | 已有文档，一字不能动 |
| 主要风险 | 设计不到位 | **静默丢文案**、把长文档做成营销页 |
| 验收重点 | 视觉质量 | 视觉质量 **+ 逐条文案比对** |

所以本案例的核心不是页面本身，而是**「保真」被做成了构建期约束，而不是态度**。

## 保真怎么做到的

**不手抄。** 文案只能从机器提取的清单注入：

```bash
# 1. 从源文档提取 102 条文案（带 id），作为唯一来源
python3 scripts/extract-copy.py <源文档.md> docs

# 2. 模板里只写占位符 {{c001}}，构建时注入；漏一条就构建失败
python3 scripts/build-page.py scripts/page-template.html docs/copy-inventory.json index.html

# 3. 验收：逐条比对渲染后的 DOM 文本（开/关 JS 各跑一遍）
node scripts/verify-copy.mjs <url> docs/copy-inventory.json
```

四项检查全部通过：

| 检查 | 结果 |
|---|---|
| 逐条精确比对（开启 JS） | 命中 **102/102**；缺失 0；被改写 0；重复注入 0 |
| 逐条精确比对（关闭 JS） | 命中 **102/102**；缺失 0；被改写 0 |
| 顺序拼接比对 | **完全一致**（逐字符） |
| 非文案文本审计 | 33 条，全部是界面标签，逐条列出供审计 |

另外有一个**独立于提取器**的复核脚本 `verify-source-coverage.mjs`：它不读清单，直接把源 markdown 逐行剥掉语法后检查每一行是否出现在页面可见文本里。它抓到过提取器与页面都漏掉的一处（见下）。

## 设计身份

**「晨光声纹台」**——一个在天亮过程中被读出来的页面。

| 隐喻 | 落到什么 |
|---|---|
| 夜 | 深蓝底 `#08131F`，未发声的状态 |
| 朝 | 一束琥珀色的光，**角度由滚动位置驱动**（205° → 157°）：往下滚，光往上走 |
| 鸣 | 声纹：一条真实绘制的连续包络，由文本散列确定性派生 |
| 标本标签 | 时间轴节点、章节编号：等宽字、小字距 |
| 手写批注 | 引用块：楷体 + 琥珀底 + 左侧笔迹线 |

字体分三个声部：**楷体**（标题、引用、收尾——"说出来的话"）、**宋体**（子标题——"文本的骨架"）、**PingFang**（正文）。标签用等宽字。

纸面颗粒由脚本在运行时生成并注入（稀疏颗粒，PNG 压缩友好），**不引入任何外部资源**。

## 四个互动（都带可见的「概念演示」标注）

1. **按住发声**——真实 Web Audio 合成（三振荡器 + 低通 + 包络），画布用 `AnalyserNode` 读实时波形；松手落回静态声纹。
2. **四个身份**——点任一身高亮，右侧示意图随之改变（新家长＝公开页、在读家长＝时间轴、老师＝课表网格、您＝一排数字）。
3. **成长时间轴**——提案 3.2 的四个要点就是四个节点，各自有自己的声纹（由该段文本派生）；「按住三秒」模拟孩子课后的三十秒，满三秒状态变为「已存进这条时间轴」。
4. **AI 音乐创作**——三种起点各合成一段五声音阶旋律，谱面随播放推进，同时生成一张抽象画面。

**为什么互动放在这四处**：提案里最关键的三件事——三个身份各看到什么、「声音成长日记」、「AI 音乐创作」——**都还不存在**。互动不是为了"让页面活泼"，是为了把还不存在的东西变得能按一遍。

### 一个必须写下来的证据边界

**对滚动驱动的页面做分段拼接全页图，本身就不是忠实表示。** 每个分段冻结的是不同的天光角度，拼起来的光带位置不等于任何一次真实浏览。本轮评审正是把拼接图当成单一状态，才得出「光不会动」的结论——实际量六个滚动位置，角度从 205° 单调走到 164.6°。**滚动驱动的视觉变化不能用全页图取证。**

## 已知边界

- **未做真人任务走查**：所有评分都是机器与单模型判断。
- **未测真机浏览器 / 微信内置内核**：只在 system Chrome 上测过。
- **未做读屏全流程**：只有 ARIA 静态断言与键盘顺序。
- **未验证真实音频输出**：只能断言状态与画面变化。
- **未采集性能**：没有 FPS 或长任务数据。
- **320×700 首屏超出**（互动组件底部 864 > 700）：320 是下限视口，验收标准定在 390×844。
- **源文档自身有一处自相矛盾**：正文写「它有三个身份，各得其所：」，紧接着的表却列了**四个**（新家长 / 在读家长 / 老师 / 您）。因为「文案不得修改」，本页**原样呈现**了这个矛盾——这是源文档需要作者定夺的地方，不是页面的问题。页面的构建方式是改一行源文档即可重新生成。

## 音色：用加法合成现场造钢琴

页面硬约束是**单文件、零外部请求**，所以不能用采样。钢琴音色用加法合成：

- **非谐泛音**：`f_n = n·f0·√(1 + B·n²)`，B ≈ 0.0006。真实钢琴弦有刚度，高次泛音比整数倍略高——这是“金属感”的来源，纯整数倍叠出来是风琴。
- **高次泛音先死**：每个分音的衰减时长随次数递减，所以音头亮、尾巴温。
- **击弦瞬态**：开头 6ms 的高通噪声当槌子；缺了它就像弦被抚而不是被敲。
- **双弦微失谐**（±0.16%）得到钢琴特有的拍音；低音延音长、高音短，按频率取。
- 总线上加 `DynamicsCompressor`——一个音 12 个振荡器，16 音旋律会重叠。

**音色不能只靠“我听着像”验收**：`scripts/verify-piano.mjs` 把页面里**真正在跑的那段合成代码**抠出来，用 `OfflineAudioContext` 离线渲染，再对渲染结果做 Goertzel 频谱与包络测量。实测：非谐偏差 **+1.8 / +6.4 / +13.3 / +28.0 / +33.5 cents**（随次数递增）、起音峰值 **7ms**、开头 5ms 有宽带瞬态、改动前那版在 3/4/5/8 倍处的能量只有新版的 **1/210 – 1/399**。全部 PASS。

> 但这证明的是**频谱与包络符合钢琴模型，不等于好听**。音色好不好听、音量够不够、真机上是不是真的发声，仍然只能由人判断，记 `NOT TESTED`。

三轮分数 **6.5 → 7.1 → 8.3**；第三轮明确写了“no blockers”，并逐条核对作者自列的禁用项**六项全部未出现**。

**两轮评审都误读了、但我验证后确认是它们对的三件事**：移动端整页截图重复首屏（`fullPage` 超限失真）、品牌词被折行拆开、`roles` 里的示意图像没加载完的占位。

**两轮评审都误读、抽查后驳回的三件事**：标题是“通用系统无衬线”（`getComputedStyle` 是宋体/楷体，canvas 逐像素墨量不同）、“常驻侧轨不存在”（`position:fixed`，截图管线产物）、桌面 hero 居中（`text-align: start`）。
