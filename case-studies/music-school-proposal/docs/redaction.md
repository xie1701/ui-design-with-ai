# redaction · 本案例的脱敏说明

本案例是一个**真实客户提案**的落地页。原件的机构名、客户称谓、所在城市与联系方式属于客户信息，不进公开仓库。仓库里这一份是**脱敏后的副本**：视觉与结构完全一致，只有少数标识性字符串被替换为占位值。

## 被替换的字段

| 字段 | 替换为 | 说明 |
|---|---|---|
| 机构名 | `青禾艺术` | 占位机构名，不对应任何真实机构 |
| 机构简称 | `青禾` | 同上（文案里出现 50 次，是替换量最大的一项） |
| 客户称谓 | `李老师` | 占位称谓 |
| 所在城市 | `本地` / `全城` | 原文为具体城市名，含搜索词与问句两种形态 |
| 联系方式 | `138 0000 0000` | 占位号码（`138 0000 0000` 是通用占位式，不是有效号码） |
| 源文档文件名 | `proposal-source-v1.1.md` | 原文件名含机构名与客户称谓 |
| 提案人署名 | **保留原样** | 提案人是本仓库作者本人，不属客户信息；仅其中的手机号已替换 |

**没有被替换的**：产品概念名「听见」、正文里所有论述、数字、结构与语气。全文 102 条文案仍是**逐字一致**的——只是把标识性名词换成了占位值。

## 怎么复核

脱敏不是"手工改一遍然后说改好了"，而是**一对一字符串替换**，可以机器复核：

```bash
# 需要原件与映射表（两者都不在本仓库内）
python3 scripts/verify-redaction.py \
  --original <原件目录> \
  --redacted . \
  --map <redaction-map.json>
```

脚本会：把映射表逐条应用到原件副本上，再与仓库里的文件**逐字节比对**。只要有一个字节对不上就报错。也就是说，本仓库里这些文件与原件之间的差异，**只能**是映射表里列出的那些字符串——不存在"顺手改了别的地方"。

映射表本身含原件真实标识，因此不随仓库分发；脚本留在仓库里是为了让复核方法可见、可复跑。

## 一处必须说清楚的副作用：派生图形会跟着变

页面里有几处图形不是画出来的，而是**由文本散列派生**的：

- 每个章节标题下方那条小的声纹刻度（构建期生成）
- 左轨 88 段声纹、顶栏进度条、首屏静态声纹（运行时生成）

它们的形状来自字符串的 FNV-1a 散列。机构名从原文换成占位名之后，这些声纹的形状**与私有原件不同**——这是替换的直接后果，不是渲染错误。`scripts/build-page.py` 每次构建都会按当前文案重算，所以仓库里这一份是自洽的：拿仓库里的模板与清单原地重建，产物逐字节一致。

## 边界

- 本仓库的 `index.html` 是**脱敏版**；作者手上的私有原件在文案上与之等价，在派生声纹形状上不同。
- 除上述字段外，未做任何其它改动。任何超出映射表的差异都应当被当作缺陷。
