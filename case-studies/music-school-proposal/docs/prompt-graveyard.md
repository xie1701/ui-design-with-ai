# prompt-graveyard · 青禾提案落地页

本轮的失效写法与它们为什么失效。**这些都是实战里真实发生过的**，不是推演。

## 1. 「文案保真」不能靠人抄

**失效写法**：把源文档的 102 条文案手抄进模板，靠通读检查有没有漏。

**为什么失效**：手抄必然出现标点漂移（全角空格 `　`、直角引号、破折号）、漏行、以及"顺手改顺一点"。更隐蔽的是**提取环节自己的静默丢件**：第一版提取脚本用 `len(norm) < 2` 过滤空条目，把表格里那个只有一个字的单元格 `您` 直接吃掉了——文案少了一条，构建却是"成功"的，没有任何报错。

**改成什么**：先用脚本把源文档切成 102 条带 id 的清单（`extract-copy.py`），文案只能从清单注入；构建时断言"每条 id 都被用到、且只用到一次"，漏一条就构建失败。验收时再逐条比对渲染后的 DOM 文本。

**教训**：保真不是态度问题，是**构建期约束**问题。人工检查只能作为第二道防线。

## 2. 用柱状均衡器画声纹

**失效写法**：声纹 = 一排等宽、等高间距的竖条，高度由数据决定。

**为什么失效**：视觉评审第一轮的原话是"它像播放器里的 stock widget，不像这个界面的一部分"。竖条阵列是**音频播放器的视觉惯例**，它表达的是"音量/频谱"，不是"一个人的声音"。而这个页面的整个立意在讲"听见"。

**改成什么**：连续包络——上下镜像的一条闭合曲线，中轴一条极细的基准线。相邻采样点做相关性平滑，两端收敛、中间饱满。它读起来像一段声音本身，而不是一个控件。

## 3. 给宋体加粗

**失效写法**：标题 `font: 600 ... "Songti SC"`。

**为什么失效**：宋体没有 600 这个字重，浏览器会**合成加粗**——把笔画横向撑开，字腔被糊住，在深底上尤其显得脏。视觉评审直接把它读成"通用系统无衬线"。

**改成什么**：展示字体一律用 400，靠**字号 + 字距**建立分量，而不是靠字重。并且把展示声部整体换成楷体：楷体的笔画粗细与起收笔本身就带表情，在任何尺寸下都不会被误读成"系统默认字体"。

**顺带纠正一条评审误读**：评审说标题"是通用无衬线"。抽查后不成立——`getComputedStyle` 的字体族是 `"Songti SC"`，且用 canvas 逐像素比对，宋体与 `sans-serif` 的墨量分别是 5964 / 7017、哈希不同；再把宋体、楷体、黑体、思源宋体、行楷五种字体**并排渲染并标注**给同一个模型看，它能正确区分。所以这是"单张缩略图判读不可靠"，不是字体没生效。**不要因为一句评审意见就去换字体族。**

## 4. 手机上把内容藏进横向滚动

**失效写法**：成长时间轴的四个节点做成 `flex` 横向滚动 + scroll-snap，390 宽度下卡片 300px，一次只看得到一张。

**为什么失效**：四个节点里有两条是提案正文的原文——把正文藏进一个"要横滑才看得到"的容器里，等于让读者可能永远读不到。而且 390 下卡片 300px、可视宽 350px，第二张只露出 50px，"这里可以滑"的提示几乎为零。

**改成什么**：<768 改成纵向堆叠（四段全部可见，靠左侧编号列建立"时间轴"的感觉）；≥768 才用横向滚动，那时一屏能并排看到 2–3 张，横滑是可发现的。

**教训**：横向滚动是**桌面**的排版手段。在手机上它会把内容变成"可能不存在"。

## 5. 满屏噪声当质感

**失效写法**：用一张 96×96 的随机 RGB 噪声当纸面颗粒，`opacity: .055`。

**为什么失效**：视觉上确实立刻不"平"了，但截图体积从 448KB 涨到 993KB（390 首屏 @2x），全页图到 4.3MB——**高熵噪声是 PNG 压缩的天敌**。而这份截图还要进公开案例库。

**改成什么**：稀疏颗粒——128×128 里只有 3.5% 的像素有颜色，其余全透明，透明度在 60–150 之间抖动。视觉上是胶片颗粒，PNG 能压缩掉大片透明区。首屏回到 681KB。

**教训**：质感要算成本。截图体积是案例库的真实约束。

## 6. 天光太淡，核心隐喻没落地

**失效写法**：`linear-gradient(角度, rgba(琥珀,.16) 0%, rgba(琥珀,.055) 32%, transparent 62%)`。

**为什么失效**：这是一个"从角落散开"的渐变，没有边界，整页看过去只像背景色不匀。评审原话："它更像是背景渐变的一点点变化，而不是一束有意的光。"

**改成什么**：让渐变有**一条边**——在 13%–25% 之间把不透明度从 .05 拉到 .22 再回落，形成一道有明确走向的光轴；再让滚动位置驱动它的角度（205° → 157°），读者往下滚，光就往上走。

**成本核算**：琥珀 22% 叠加后，最暗的次要文字（`#A9B4C2`）对比度从 8.90:1 降到 5.72:1，仍高于 AA 4.5:1。**所以 22% 是算过的上限，不是随手取的。**

## 7. 「有互动」不等于「互动有意义」

**失效写法**：为了凑"互动性"，加一个装饰性的、和内容无关的动效（比如随滚动淡入的卡片）。

**为什么失效**：这个页面的提案里有三件事**本来就不存在**——三个身份各看到什么、「声音成长日记」、「AI 音乐创作」。真正有价值的互动是**把还不存在的东西变得可以按一遍**：按下确认才长出来的产物、按住三秒留下的那段声音、选一个起点就编出来的曲子。

**改成什么**：四个互动全部落在"演示一个尚不存在的机制"上，而不是落在"让页面动起来"上。并且每个都带可见的「概念演示」标注——因为让提案里的东西看起来像已上线功能，是**反效果**。

**教训**：互动性要服务于"这个提案最需要被理解的那一件事"，不是服务于"这个页面需要显得活泼"。
