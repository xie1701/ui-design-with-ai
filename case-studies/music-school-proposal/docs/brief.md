# brief · 青禾艺术「听见」线上成长空间 · 提案落地页

- 模式：`CREATE`（主）+ `COMPONENT`（互动组件）
- 源文档：`proposal-source-v1.1.md`（10,616 bytes / 183 行）
- 文案清单：`docs/copy-inventory.json`（102 条，由 `scripts/extract-copy.py` 机器提取，作为唯一文案来源）
- 日期：2026-09-21

## Design Read

> 这是一个面向**青禾艺术主理人李老师（首要读者）与后续家长/同行访客**的**单页展示型落地页（Web，手机优先）**，解决**一份文字提案里的空间与机制只能被想象、不能被走一遍**，采用**晨昏光谱 × 声纹**的视觉语言，优先保证**提案文案零缺失零改写、手机可读、至少三处真实可操作的互动**。

## 当前行为与可观察障碍

| 当前行为 | 可观察障碍 |
|---|---|
| 提案是一份 markdown/文档，靠通读理解 | 最关键的三件事——三个身份各看到什么、「声音成长日记」、「AI 音乐创作」——**都还不存在**，读者没有任何可以看、可以按的对象 |
| 文档 3.1 用文字描述"开场就是青禾的气质：深蓝的底、一束朝阳的黄" | 这句话本身就是对**视觉**的描述，用文字承载它的成本最高、说服力最低 |
| 提案反复强调"被听见" | 「听见」这件事在文档里是**名词**；读者只能读到这个词，听不到、按不到、翻不动 |

**问题陈述（可验证）**

> 李老师在读这份提案时，只能在文字里想象「听见」这个空间长什么样，因为提案里最关键的三件事都还不存在，没有任何可以看、可以按的对象；解决后应看到：访客在 390×844 首屏内就知道这是青禾的线上成长空间，并且能亲手按下至少三处把抽象机制变具体的互动。

## 硬约束

1. **文案主体不得缺失或修改**（用户明示）。落地方式：文案不手抄——由 `scripts/extract-copy.py` 从源文档机器提取 102 条，构建时注入模板；验收时逐条在渲染 DOM 文本中比对。
2. 单文件、零外部依赖、零网络请求（离线可开）。
3. 页面必须**明确标注**哪些是概念演示：提案里的功能都还不存在，页面不能让它看起来像已上线。

## 非目标

- 不做真实录音、上传、登录、后端。互动全部在前端本地完成。
- 不做真实 AI 音乐生成。用 Web Audio 做**确定性合成**，并在界面上标注为概念演示。
- 不改写、不精简、不"优化"任何一句提案文案；不新增任何数字、承诺或效果声明。
- 不做英文版、不做暗色/亮色双主题切换。
- 不重做提案的信息架构：章节顺序（一~七）与内容归属不变。

## 目标视口与状态

目标视口：390×844（首要）、320×700（下限）、768×1024、1440×900。
输入方式：触摸优先，指针与键盘同等可用。

## 风险与待决

| 风险 | 影响 | 处置 |
|---|---|---|
| 提案含真实客户名与手机号 | 若作为**公开**案例推到 GitHub，会暴露客户与个人信息 | 页面本身按原文保留（属"文案主体"）；**公开案例是否脱敏需用户决定**，默认不推 |
| 互动容易被误读为"功能已存在" | 损害提案可信度 | 每个互动组件带可见「概念演示」标注；页脚统一声明 |
| 长文档在手机上易读性差 | 读者流失 | 目标视口优先 390；正文行宽、字号、行高按移动端定 |
| Web Audio 被浏览器策略阻止 | 互动失效 | 全部音频由显式用户手势触发；不可用时降级为静默并给出文字反馈 |
