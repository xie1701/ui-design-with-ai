# 证据链与内化结论

## 一手材料

1. **Lenny Rachitsky — How to turn your AI into a world-class designer**
   https://www.lennysnewsletter.com/p/how-to-turn-your-ai-into-a-world
   - LLM 的默认行为偏向最可能、最安全的选择，容易形成 design-by-committee。
   - 借鉴 Double Diamond：Discover 发散，Define 建立身份，Deliver 打磨。
   - 先广后深；用外部 String Seed of Thought、具体而大胆的视觉隐喻扩大搜索空间。
   - 用独立 critic 只看截图，不看代码；提供明确质量基线和可执行反馈。
   - 用大模型做少量高杠杆评审，小模型做重复实现；设定停止条件防止烧 token。
   - 用图片/视频增强代码无法自然表达的材质与运动，但需逐帧验证。
   - 最后做减法：删掉无价值标签、容器、渐变、glow 和自定义但更差的控件。

2. **附件视频：如何使用 AI 做出顶级的 UI 设计**
   - 约 26 分 49 秒，640×480 主视频流；完整口述转录已分成 9 段，合并保存于 [`transcript_packed.md`](/Users/jerry/cola/coding-cola/project-20260920-130757-c5e58081/analysis/video/transcript_packed.md)。ASR 仅作检索依据，口误、同音错字和标点需回看视频复核。
   - 视频讲解者明确把 Double Diamond 说成四步：Discover（发散观察问题）、Define（聚焦核心问题）、Develop（发散解法）、Deliver（收敛交付）。核心不是从想法直接跳到界面，而是两次“发散—收敛”。
   - 视频把“用户拍照识别热量”作为反例：这只是设计者想到的解法，不能直接当成用户需求；应先探索用户在记录热量时遇到的真实问题，再比较拍照、语音描述等多种解法，必要时通过小范围分发/灰度试用收敛。
   - 视频讲解者对 String Seed 做了重要降级：字符串可以帮助增加发散，但不是关键；只要明确要求多个不同的配色、布局和字体风格，也能得到差异，真正关键是从模型外部注入具体、多样、带品味的输入。
   - 视频给出的实践链条是：先让 AI 广泛提出设计语言，再由人加入喜欢/不喜欢、避免项和感官体验（如触感、声音、质感），继续迭代设计意向，最后直接让 AI 实现，不必机械地把长提示词复制到新对话。
   - 视频把独立 Critic 解释成“去除历史包袱”：执行 Agent 受既有代码和上下文锚定，新的评审 Agent 只看截图和目标质量，才能提出结构性突破；评审反馈必须具体到实现 Agent 能改代码的程度，不能停在“更高级”的意向描述。
   - 视频后半段新增了两条重要实践：AI 生成的产品文案质量往往不够，应由人亲自写/重写；图片、shader、3D 和视频可以增加个性，但必须服务于设计，不是装饰堆叠。
   - 视频中的媒体实践包括：生成单色背景的循环视频、用 chroma key/抠像转成透明素材、按鼠标或滚动位置逐帧播放、用连续首尾帧制作一镜到底效果；这些都必须做性能、移动端和逐帧验收。
   - 本文件把视频中演示性提示词提升为跨项目原则；未经画面或原文直接证实的细节不当作规范。

## 权威边界

3. **公众号文章：如何让 AI 做出世界级的 UI 设计（永燃的思维火花 · Jerold，2026-09-18）**
   https://mp.weixin.qq.com/s/DAC9i5BwNcnHCa-_DNh3DA
   同样以 Lenny 原文为底，额外做了几项工程化延伸，已被本 Skill 吸收：
   - **Subtraction Pass**：最终收敛轮禁止新增，只允许删除/合并/简化/弱化/重排，并对每个元素问三个问题（信息功能？层级/品牌？删了会变差吗？）。
   - **AI Tells Audit**：独立于减法的一轮模板化审查，目标是让设计看起来 Intentional 而不是 Generated。
   - **参考图即 Visual Loss Function**：与其用文字描述“简洁/高级”，不如直接给一组 Quality Bar 图像；参考图是基准和 Moodboard，不是复制对象。
   - **Harness Engineering 总框架**：编排实现者、Critic、图像/视频工具和减法收敛；Prompt 解决一次任务，Harness 解决以后所有任务（已落成 `references/master-prompt.md` 总控模板）。
   - **禁用词表**：Modern/Beautiful/Clean/Premium 这类词没有设计信息，须翻译成具体视觉决策（已入 SKILL §1）。
   - **Critic 不为成本降标 + 相对排序协议**：评审不考虑实现成本；必要时用“4 专业 + 1 我们的”排序替代绝对评分（已入 SKILL §5、critic-prompt.md）。
   - 注意：该文明确标注 Technique 7 起进入原文付费墙，AI Tells Audit 等是该作者的自我延伸，不是原文原句；引用时区分。
4. **Nielsen Norman Group — 10 Usability Heuristics**
   https://www.nngroup.com/articles/ten-usability-heuristics/
   用系统状态可见性、现实世界匹配、用户控制、 一致性、错误预防等检查“好看但不好用”的界面。

5. **Nielsen Norman Group — Using AI for UX: Study Guide**
   https://www.nngroup.com/articles/ai-work-study-guide/
   AI 时代更稀缺的是发现用户需求、定义意图、监督和判断，而不只是生成。

6. **W3C — Web Content Accessibility Guidelines (WCAG) 2.2**
   https://www.w3.org/TR/WCAG22/
   用于对比度、键盘、焦点、目标尺寸、替代文本和动态内容的验收；具体等级按项目要求确定。

7. **Apple Human Interface Guidelines**
   https://developer.apple.com/design/human-interface-guidelines
   需要 Apple 平台原生感时，优先参考官方布局、字体、材料和动效，而不是把“Apple-like”当成渐变和圆角滤镜。

8. **Material Design 3 Foundations**
   https://m3.material.io/foundations
   用于 Material 平台的结构、排版、颜色、交互状态和无障碍基础；不与另一套设计系统混用。

9. **Figma Design Crit**
   https://www.figma.com/solutions/design-crit/
   支持“选择对象—请求评审—查看反馈—采取行动”的评审闭环；它强化了把批评做成独立工作阶段的实践。

## 举一反三扩展（本轮新增）

以下不在视频/原文中，是从方法论推演后落到 Skill 的扩展：

- **失败提示词库（prompt-graveyard）**：来自 Lenny 原文“save the prompts that don't work, test again when newer models come out”，工程化为 §7 工件与跨会话维护规则。
- **故意试不可能的方向**：来自原文“Don't be afraid to try ideas that sound terrible”，落成 §2.4 探索规则。
- **并行独立实例**：原文用 4 个 Claude Code 实例做实验；推演为 §2.3 常规探索手段——同一 brief 多实例采样，比单次输出里的“四个风格”更真地覆盖设计空间。
- **评审 token 预算**：原文提到 Critic 占比 <10% 输出；推演为健康度指标和越权检测信号（§5）。

## 后续可继续探索（含暂不写入的原因）

以下方向已识别但刻意不写入当前 SKILL，逐条说明原因与启用条件：

1. **跨项目设计身份模板库**
   - 内容：把 design-identity.md 沉淀为可复用模板（控制面板系、编辑物系、游戏系等），新项目从最近邻模板起步。
   - 暂不写入的原因：没有真实项目积累前，模板库会是未经检验的空架子，反而强化模板化——与 Skill 的反默认目标自相矛盾。
   - 启用条件：完成 ≥3 个真实项目且产出 ≥3 份差异明显的设计身份后，提炼共性结构。

2. **QA 清单自动化脚本**（对比度计算、断点截图、状态覆盖检测）
   - 内容：把 §6.3 验收清单中可机器检查的部分变成脚本，减少人工走查。
   - 暂不写入的原因：脚本绑定技术栈（Playwright/Puppeteer/语言），现在选定是在没有目标项目的情况下猜约束；写错栈的脚本比没有脚本更浪费。
   - 启用条件：首个真实项目确定技术栈后，把实际用到的检查抽成 `scripts/`。

3. **视频逐帧验收标准化**（帧采样 + 差异检测脚本）
   - 内容：把 §4.4 的“逐帧检查”从人工看变成采样对比脚本。
   - 暂不写入的原因：属媒体技能交叉，且现有 video-use 技能已覆盖相邻能力；在 UI 项目首次真实用到视频资产前实现，是为假想需求写代码。
   - 启用条件：某个 UI 项目真正嵌入生成视频且逐帧问题首次出现时，从那次修复中抽取脚本。

4. **真实用户测试协议**（5 人可用性访谈脚本、任务走查模板）
   - 内容：SKILL 已要求“Critic 评分不能替代用户测试”，但未提供怎么做。
   - 暂不写入的原因：访谈方法学是独立领域（GOV.UK 等有成熟公开指南），塞进本 Skill 会稀释焦点；且脉动的产品多为早期验证阶段，测试对象和形式差异大。
   - 启用条件：某个产品进入真实用户验证阶段时，单独做一个 user-testing 技能，本 Skill 只保留引用。

5. **模型评审能力基线测试**（同一截图组自动交给多模型评审并对比建议质量）
   - 内容：把 §5 的“用一轮小样本测试选评审模型”自动化。
   - 暂不写入的原因：依赖当前可用的模型清单和调用方式，模型格局变化快；硬编码会很快过期。
   - 启用条件：工具链稳定后做成可选脚本；近期保持人工小样本测试即可。

6. **旋钮推断决策表**（brief 信号 → 三旋钮默认值的完整映射）
   - 内容：§1 只有几条定性规则（严肃 B2B 降 variance 等），可扩展为信号→默认值的完整决策表。
   - 暂不写入的原因：当前规则已够用，完整表需要使用数据支撑；拍脑袋填满 10×3 格子是伪精确。
   - 启用条件：跨会话使用中积累到 knob 设置与结果质量的对应记录后回填。

## 需要谨慎内化的地方

- Double Diamond 必须保留完整的四阶段：Discover/Define 处理“问题钻石”，Develop/Deliver 处理“解法钻石”；视觉方向探索属于第二个钻石，不应替代第一钻石的用户问题发现。
- “随机种子”只扩大探索，不保证美感；视频讲解者自己也认为明确指定多组配色、布局和字体可能比字符串更关键；必须由用户任务、品牌、可用性和 critic 收敛。
- “9/10”是视频案例里的工作流停止信号，不是客观审美真理，也不能取代真实用户测试。
- 大模型/小模型的具体分工会随模型能力、成本和工具变化；稳定的应是角色协议、输入隔离和证据输出，而不是某个模型名称。
- 生成图片/视频不能掩盖信息架构问题；先验证问题、任务和状态，再加材质与动效。
- AI 生成文案尤其需要人工把关；抽象隐喻、空洞品牌词和过度解释会直接制造“AI 味”。
- 文章中的 API key 示例只是演示语境；实际工作流必须使用受限、可撤销、不会进入代码或聊天记录的密钥。

## 端到端实跑回修（2026-09-20，住明白首页）

实测验证后写回 SKILL 的三条流程修正：

1. **截图管线检查（§5）**：Chrome headless=new 的 window-size 不可信（请求 390 实际 756 布局，注入脚本读 clientWidth 证实），两轮 Critic 因此基于失真输入"确认"了不存在的 bug；可靠方案为 `npx playwright screenshot --channel=chrome --viewport-size=... --full-page --wait-for-timeout=1500`。含入场动画页面必须等动画完成再截图，否则半透明中间帧会被当成"残影/低对比度"。
2. **Critic 多模态回退（§5）**：平台无读图能力时降级为"文字代理评审"并标注，结论降级为参考。
3. **并行实例标注资源条件（§2.3）**：多实例发散标注"资源允许时"，单人单会话退化为文字发散，不阻塞流程。

未回修但已记录于 PROBLEMS.md 的经验：评审员事实性陈述需抽查（曾误读便签内容）；视觉异常先用 DOM 度量定位根因再决定改页面还是修管线。
